# Поддержка OData v4

Что библиотека умеет на самом деле. Таблицы построены по фактическому поведению версии 1.0.3
(проверено запуском, не выведено из кода). Легенда:

- ✅ работает;
- ⚠️ работает с оговоркой — читайте примечание;
- ❌ не работает: молча игнорируется, даёт битый SQL или ошибку парсера.

---

## Системные query options

| Опция | Статус | Примечание |
|---|---|---|
| `$filter` | ⚠️ | Сравнения, `and`/`or`, скобки и часть функций — да. `not`, арифметика, `in`, лямбды — нет (см. ниже) |
| `$select` | ✅ | Включая `Nav/Field` при наличии `$expand` |
| `$orderby` | ⚠️ | По полям корня — да. По полям связи ломается, если связь ещё и в `$expand` (дефект A-02) |
| `$top` | ⚠️ | Не валидируется: отрицательный молча игнорируется, слишком большой валит парсер |
| `$skip` | ✅ | |
| `$count` | ⚠️ | **Включён по умолчанию** — отклонение от спецификации, см. ниже |
| `$expand` | ⚠️ | Вложенные `$select` / `$filter` / `$orderby` — да. Вложенные `$top` / `$skip` игнорируются |
| `$search` | ⚠️ | Упрощённая семантика: вся строка как одна подстрока. Грамматика `"a b" AND NOT c` не разбирается |
| `$apply` | ❌ | `Fail at 0` от парсера |
| `$compute` | ❌ | `Fail at 0` от парсера |
| `$format` | ❌ | Ответ всегда JSON |
| `$levels` | ❌ | |
| `$skiptoken` | ❌ | Пагинация по токену не поддерживается, только `$top` / `$skip` |

### `$count` включён по умолчанию

Главное отличие от спецификации, о которое спотыкаются первым делом.

| Запрос | Ответ |
|---|---|
| `GET /api/users` | `{ "items": [...], "count": 42 }` |
| `GET /api/users?$count=false` | `[...]` |
| `GET /api/users?$count=true` | `{ "items": [...], "count": 42 }` |

По спецификации OData отсутствующий `$count` означает `false`. Здесь — `true`.
Практические следствия:

- возвращаемый тип — объединение `T[] | GetManyResponse<T>`, его нужно сужать на стороне вызова;
- каждый запрос по умолчанию делает **два** обращения к БД (`getManyAndCount`).
  Если счётчик не нужен, передавайте `$count=false` — это заметно дешевле.

## Операторы `$filter`

### Сравнение

| Оператор | SQL | Статус |
|---|---|---|
| `eq` | `=` (или `IS NULL` для `null`) | ✅ |
| `ne` | `<>` (или `IS NOT NULL`) | ✅ |
| `gt` | `>` | ✅ |
| `ge` | `>=` | ✅ |
| `lt` | `<` | ✅ |
| `le` | `<=` | ✅ |
| `in` | — | ❌ `Unexpected character at N` |
| `has` | — | ❌ |

### Логика

| Оператор | Статус | Примечание |
|---|---|---|
| `and` | ✅ | |
| `or` | ✅ | |
| `( )` | ✅ | `(a eq 1 or b eq 2) and c eq 3` → `(u.a = :p0 OR u.b = :p1) AND u.c = :p2` |
| `not` | ❌ | **Фильтр молча исчезает**, вернётся вся таблица. Дефект A-11 |

### Арифметика

`add`, `sub`, `mul`, `div`, `mod` — ❌ все. Дают битый SQL (`" = :p0"` без левой части)
и ошибку СУБД. Обходной путь: считать на стороне БД через вычисляемую колонку либо
фильтровать по готовому полю.

### Лямбда-операторы

`any`, `all` — ❌. `$filter=posts/any(p: p/title eq 'x')` компилируется в `"u.posts"`.
Обходной путь для «есть хотя бы одна связанная запись, удовлетворяющая условию» —
фильтр по пути связи: `$filter=posts/title eq 'x'` (даёт `LEFT JOIN` + условие,
семантика ближе к `any`, но с дублированием строк корня).

## Функции `$filter`

| Функция | Генерируемый SQL | Статус |
|---|---|---|
| `contains(f, 'x')` | `f like '%x%'` | ⚠️ дефект A-01 при смешивании с `eq` |
| `startswith(f, 'x')` | `f like 'x%'` | ⚠️ то же |
| `endswith(f, 'x')` | `f like '%x'` | ⚠️ то же |
| `indexof(f, 'x')` | `INSTR(f, 'x') - 1` | ⚠️ нет в PostgreSQL и MS SQL |
| `tolower(f)` | `LOWER(f)` | ✅ |
| `toupper(f)` | `UPPER(f)` | ✅ |
| `trim(f)` | `TRIM(' ' FROM f)` | ⚠️ нет в SQLite, в MS SQL только 2022+ |
| `length(f)` | `LEN(f)` | ⚠️ только MS SQL; в остальных нужен `LENGTH` |
| `round(f)` | `ROUND(f)` | ✅ |
| `floor(f)` | `FLOOR(f)` | ✅ |
| `ceiling(f)` | `CEILING(f)` | ⚠️ в SQLite нет |
| `year/month/day(f)` | `YEAR(f)` и т.п. | ⚠️ нет в PostgreSQL (`EXTRACT`) и SQLite |
| `hour/minute/second(f)` | `HOUR(f)` и т.п. | ⚠️ то же |
| `now()` | `NOW()` | ⚠️ нет в SQLite и MS SQL |
| `substring` | — | ❌ битый SQL |
| `concat` | — | ❌ битый SQL |
| `replace` | — | ❌ битый SQL |
| `date`, `time` | — | ❌ битый SQL |
| `cast`, `isof` | — | ❌ битый SQL |
| геопространственные | — | ❌ |

Функции с ⚠️ по переносимости выбираются без учёта реальной СУБД: `TypeOrmVisitor` жёстко
работает в режиме `SQLLang.Oracle`, а имена функций зашиты константами. Полностью безопасны
на всех поддерживаемых TypeORM СУБД только `LOWER`, `UPPER`, `ROUND`, `FLOOR`.

## `$expand`

| Возможность | Статус | Пример |
|---|---|---|
| Простая связь | ✅ | `$expand=posts` |
| Несколько связей | ✅ | `$expand=posts,profile` |
| Вложенный `$select` | ✅ | `$expand=posts($select=id,title)` |
| Вложенный `$filter` | ✅ | `$expand=posts($filter=title eq 'x')` — фильтр попадёт в `ON`, а не в `WHERE` |
| Вложенный `$orderby` | ✅ | `$expand=posts($orderby=id desc)` |
| Вложенный `$expand` | ✅ | `$expand=posts($expand=comments)` |
| Вложенный `$top` / `$skip` | ❌ | Разбирается, но игнорируется — вернутся все связанные записи |
| Вложенный `$count` | ❌ | |
| `$expand` + `$filter` по той же связи | ❌ | Ошибка СУБД, дефект A-02 |
| Повторный `$expand` одной связи | ⚠️ | Работает, но делает два `LEFT JOIN`, дефект A-04 |

Все JOIN — `LEFT`: `$expand` не отсеивает сущности без связанных записей.

## `$search`

Реализован собственным кодом, минуя грамматику OData.

**Семантика:** строка целиком ищется как подстрока (регистронезависимо) во всех текстовых
колонках корневой сущности; если строка приводится к числу — дополнительно проверяется
точное равенство во всех числовых колонках. Условия объединяются через `OR` в скобках
и добавляются к запросу через `AND`.

```
GET /api/users?$search=42
  → AND (
      LOWER("User"."name")  LIKE LOWER('%42%') OR
      LOWER("User"."email") LIKE LOWER('%42%') OR
      "User"."id" = 42
    )
```

**Что не поддерживается:**

- грамматика OData: `"фраза в кавычках"`, `AND` / `OR` / `NOT` между термами;
- поиск по колонкам заджойненных связей — только корневая сущность;
- работа с нестандартной `namingStrategy` (дефект A-05).

**Типы колонок, участвующие в поиске**

| Категория | Типы |
|---|---|
| Текстовые (LIKE) | `varchar`, `character varying`, `char`, `character`, `text`, `citext`, `nvarchar`, `nchar`, `ntext`, `tinytext`, `mediumtext`, `longtext`, `string` |
| Числовые (равенство) | `int`, `int2`, `int4`, `int8`, `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `float`, `float4`, `float8`, `double`, `double precision`, `real`, `number` |

Осознанно исключены `uuid`, `json` / `jsonb`, `enum`, `date` / `timestamp`, `bytea` / `blob`:
`LIKE` по ним либо бессмысленен, либо роняет запрос на приведении типов.

**Производительность:** `LIKE '%…%'` не использует B-tree индексы — это последовательное
сканирование по всем текстовым колонкам. На больших таблицах вместо `$search` стоит
подключать полнотекстовый поиск СУБД.

## Совместимость с СУБД

Библиотека не адаптирует SQL под конкретный драйвер, поэтому поведение зависит от того,
какие возможности вы используете.

| Возможность | PostgreSQL | MySQL | SQLite | MS SQL |
|---|---|---|---|---|
| `$filter` (сравнения, логика) | ✅ | ✅ | ✅ | ✅ |
| `$select`, `$orderby`, `$top`, `$skip` | ✅ | ✅ | ✅ | ✅ |
| `$expand` | ✅ | ✅ | ✅ | ✅ |
| `contains` / `startswith` / `endswith` | ✅ | ✅ | ✅ | ✅ |
| `$search` | ✅ | ❌ цитирование `"…"` | ✅ | ⚠️ зависит от `QUOTED_IDENTIFIER` |
| `$search` + `namingStrategy` | ❌ | ❌ | ❌ | ❌ |
| `length`, `now`, `indexof`, `trim` | ⚠️ | ⚠️ | ⚠️ | ⚠️ |

Регулярно проверяется в CI только SQLite (интеграционные тесты). Остальные СУБД —
по коду и документации; своя проверка перед внедрением обязательна.

## Сводка «чего ждать»

**Работает надёжно:** `$filter` со сравнениями, `and` / `or` и скобками; `$select`;
`$orderby` по корню; `$top` / `$skip`; `$count`; `$expand` со вложенными `$select` и `$orderby`;
`contains` / `startswith` / `endswith` по отдельности; `$search` на стандартных именах колонок.

**Требует осторожности:** смешивание LIKE-функций с обычными сравнениями в одном `$filter`
(A-01); `$expand` вместе с фильтром по той же связи (A-02); любые функции, кроме
`LOWER` / `UPPER` / `ROUND` / `FLOOR`, вне PostgreSQL.

**Не работает:** `not`, арифметика, `in`, `any` / `all`, `$apply`, `$compute`, `$levels`,
`$skiptoken`, вложенная пагинация в `$expand`.

Планы по закрытию пробелов — в [roadmap.md](./roadmap.md).
