## Три вещи, которые удивляют в первую очередь

1. **Форма ответа зависит от `$count`.** Без него — массив, с `$count=true` —
   `{ items, count }`. Возвращаемый тип поэтому объединение, и его нужно сузить на
   стороне вызова. Подробности:
   [odata-support.md](./odata-support.md#форма-ответа-и-count).
2. **Приоритет `not` ниже, чем в спецификации.** Парсер читает `not (X) and Y` как
   `not (X and Y)`; нужны явные скобки. Подробности:
   [odata-support.md](./odata-support.md#приоритет-not).
3. **Неподдерживаемое отвергается, а не игнорируется.** `in`, лямбды `any` / `all`,
   `$apply` и прочее дают `ODataUnsupportedError` (в HTTP — 400). Библиотека никогда не
   выполняет запрос частично и не возвращает молча не те данные.
